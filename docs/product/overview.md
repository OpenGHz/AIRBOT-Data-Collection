# 产品概览

## Problem

机器人学习需要大量高质量、多模态、时序对齐的数据，但现实采集往往同时面临以下问题：

- 硬件链路复杂，机器人、相机、示教器和控制器组合多样
- 采集流程不统一，保存、删除、回放、检查常常依赖临时脚本
- 数据格式分散，后续训练、可视化和诊断成本高

AIRDC 的目标是把这些问题收敛为一个可配置、可扩展、可重复运行的数据采集框架。

## Users

- 采集操作员 / 现场集成工程师
- 数据 / 算法工程师
- 平台维护者 / 扩展开发者

## Requirements

- 支持配置驱动的机器人与相机组合装配
- 支持实时可视化与可控的采集流程
- 支持按 episode 保存结构化数据与元信息
- 支持对已采集数据做检查、可视化和转换
- 支持从真机手动采集扩展到仿真 / 自动采集

## Non-Goals

- 不以通用机器人控制框架为目标
- 不以内置完整云端数据平台为目标
- 不承诺 Windows 或 macOS 作为当前一等运行平台

## Success Metrics

- 新的机器人 / 相机组合可以主要通过配置完成接入
- 采集后的数据能被稳定读取、可视化和检查
- 维护者能在不修改主循环的前提下扩展 sampler、manager 或 demonstrator
- 真机模式和自动化模式共享同一套核心运行时

## 当前产品边界

当前仓库已经具备：

- AIRBOT 相关的真机采集默认配置
- MCAP 为主的数据保存路径
- 可视化、检查、转换与部分上传能力
- `auto-atomic-operation` 对接能力

当前仓库尚未完全产品化的部分包括：

- 统一的 docs site 导航与信息架构
- 对更多非 AIRBOT 设备的开箱即用配置
- 对所有可插拔模块的系统性兼容性矩阵
